# Работа над обновлениями

- Отправляйте изменения на GitHub и выпускайте новую версию только после пяти законченных пользовательских улучшений со времени последней публикации либо по прямой команде пользователя.
- Одно изменение — одно законченное улучшение или исправление из запроса пользователя. Файлы, коммиты и промежуточные правки по одной задаче отдельно не считаются.
- Ведите список ещё не опубликованных улучшений в `docs/pending-updates.md`. До готовности очередного пакета работайте и проверяйте изменения локально. Локальные коммиты допустимы.
- Номер версии и описание релиза обновляйте при подготовке публикации пакета. После успешной публикации начинайте новый список.

## Интерфейс

Для продуктовых изменений интерфейса используйте Lazyweb согласно инструкциям родительского рабочего пространства. Для backend/CLI/infra-работ поиск референсов не требуется.

- Между историей чата и полем ввода используется статический градиент высотой 48 px в цвет текущей темы. Сохраняйте доступность нажатий, кнопку прокрутки поверх градиента и отступ последнего сообщения: внизу истории его текст и действия должны быть полностью видимы.

## Сессии и рабочие файлы

- «Новая сессия» открывает стартовый экран без сохранения пустого чата. Выбор проекта необязателен; сессия создаётся при первом сообщении или явном открытии инструмента рабочей панели.
- Для чата без проекта `store.ensureWorkspace` создаёт отдельную папку в системной «Документы/Turwe/Projects» при `CreateWorkspace` или первой записи `FileWrite`. Субагенты используют папку основного чата. Разговор и чтение контекста не должны создавать папки.
- `FileRead`, `Glob` и `Grep` могут читать нужный контекст вне рабочей папки через общий механизм разрешений. Запись, редактирование, патчи и откат остаются внутри проекта/worktree; не ослабляйте общий `inside` ради внешнего чтения. Абсолютные пути и ссылки должны учитывать правила запрета исходного проекта.

## Подключения MCP

- Не заменяйте все ошибки Figma предположением об одобрении клиента. `mcp-errors.cjs` формирует безопасные диагностические данные из фактического этапа, HTTP-кода и сетевых ошибок; сырые ответы OAuth не должны попадать в чат.
- OAuth выбирает способ регистрации из метаданных сервера. Сохраняйте восстановление SDK после ошибок токенов, PKCE и системное шифрование. Результаты текущей проверки: `docs/mcp-connection-verification.md`.

## Разрешения и панели

- Постоянные разрешения на инструмент сохраняются только после явного выбора пользователя. Области: проект (включая его чаты/worktree) и все проекты. Решения модели проверки никогда не сохраняются. Ручной режим по-прежнему спрашивает каждый раз; постоянная область из карточки явно переключает его в упрощённый. Подробности: `docs/permissions-verification.md`.
- Движение правых виджетов использует ту же `fluid.slow`, что SidebarRail. Сохраняйте exit-анимацию, reduced motion, состояния редактора и скрытие нативного браузера во время движения: CSS clipping не ограничивает WebContentsView.
