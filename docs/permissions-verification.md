# Проверка новых режимов разрешений

Включено в пакет 0.6.18.

Проверено:

- Ручной режим запрашивает подтверждение чтения и изменений, в том числе ранее разрешённых. Упрощённый и авто используют только человеческие разрешения или явные правила проекта.
- Авто вызывает отдельную сохранённую модель: автоматически Haiku, затем Sonnet, либо выбранный пользователем ID. Вызов идёт через существующее подключение API, без инструментов у проверяющей модели. Неизвестный ID, отсутствие модели, отказ, тайм-аут и неправильный ответ не разрешают действие.
- Решения модели относятся к одному вызову. Повторное действие проверяется снова. «Разрешить один раз» не создаёт запись, «Запомнить только этот вызов» сохраняет хеш точного инструмента, параметров и рабочей папки. Проверены границы проекта, worktree и подключения MCP.
- Меню «Всегда разрешать…» сохраняет человеческое разрешение для текущего инструмента во всём проекте (включая другие чаты и worktree) или глобально. Разрешение привязано к определению инструмента и конфигурации MCP; разные аргументы разрешены. Хранятся только хеши, без копирования команд и секретов. Глобальная область работает также без выбранного проекта.
- В ручном режиме меню заранее сообщает о переходе в упрощённый режим при выборе постоянной области. Повторный выбор ручного режима снова включает каждый запрос. Запреты, правила ask, режим плана и ограничения профиля сильнее сохранённых разрешений.
- «Доступ и LSP» отдельно отзывает разрешения проекта/чата и глобальные разрешения. Счётчики обновляются во время работы. Проверены IPC, сохранение после перезапуска, изменение параметров, отмена и смена контекста до исполнения.
- Отмена, запоздалый ответ проверки, смена режима и новое правило deny не запускают уже запрещённое действие. Опросы пользователя не принимаются автоматически. Очередь и субагенты используют актуальный режим родительского чата.
- Смена API переключает выбор модели проверки; удаление выбранной модели возвращает автоматический выбор. Настройка сохраняется после перезапуска.
- В обычных режимах неразрешённые файлы не подгружаются в контекст без проверяемого вызова инструмента. «План» и явные правила чтения сохраняют автоматический контекст разрешённых файлов.
- Режим «Ебашим на все бабки» обходит подтверждения, модельную проверку и правила разрешений проекта. Валидация параметров, профили доступных инструментов, защита от устаревших правок и права ОС продолжают действовать.

Автоматические проверки: полный набор Node, дополнительные сценарии в `action-review.test.cjs`, проверка текста действий и контекста проекта; TypeScript и Vite production build.

Интерфейс: настоящий Electron на Windows с отдельным профилем, имитатором API на границе HTTP и реальным файловым инструментом. Проверены подтверждение, запоминание, повторный вызов без вопроса, новая модельная проверка, отказ, неправильный ответ, bypass, выбор модели через IPC и сохранение на диске. Тестовый API позволяет проверить механику, но не измеряет качество решений конкретной облачной модели.

Дополнительно проверены темы ChatGPT (1280 × 850) и Claude Code (800 × 700): меню режимов, кнопки подтверждения, состояние проверки и настройки. Артефакты находятся вне репозитория в `Artifacts/turwe-code/permissions`. macOS в этом цикле локально не запускалась; публикация и CI-сборки платформ отложены до готовности пакета.

Поиск UI-референсов: [Lazyweb Agentic Search](https://www.lazyweb.com/agentic-search/9eae7efe-6e7b-4e01-8c5f-45f0e034b83d). Подходящих экранов выдача не дала; использованы существующие компоненты приложения.
