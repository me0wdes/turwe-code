# Работа с кодом в Turwe Code 0.6.0

Откройте папку проекта в поле ввода. Плюс в правом верхнем углу чата добавляет инструмент в рабочую панель. Одновременно доступны любые два инструмента из списка. Перетаскивайте их за заголовок к краям области справа, чтобы расположить рядом или друг над другом. То же можно сделать через три точки в заголовке; там же доступны обмен местами и одинаковый размер. Левый край меняет общую ширину, разделитель между панелями — пропорции. Раскладка сохраняется для проекта; на узком окне панели располагаются вертикально.

## Этап A: файлы, команды и проверка изменений

Агент получает FileRead, FileWrite, FileEdit, apply_patch, Glob и Grep. Поиск работает через ripgrep, а адреса файлов привязаны к выбранному проекту или worktree. При полной перезаписи существующего файла требуется hash последнего чтения. Точные замены сохраняют CRLF Windows и останавливаются при неоднозначном совпадении. Секретные файлы и выход через симлинки не доступны этим файловым инструментам.

В «Файлы и редактор» можно искать по пути и тексту, открыть код, изменить и сохранить его. Несохранённый черновик остаётся при закрытии панели и переключении чатов в текущем запуске. Изменение файла другим процессом вызывает конфликт вместо перезаписи.

«Терминал» запускает PowerShell или Bash из Git for Windows. Интерактивный терминал использует ConPTY; команды агента возвращают вывод, exit code и ID процесса. Фоновые процессы продолжают работать между ответами. Основной чат видит и может останавливать процессы своих субагентов. Закрытие приложения завершает его процессы.

В «Изменения» показан diff правок файловыми инструментами. Можно отправить агенту комментарий с файлом и строкой, запустить отдельного ревьюера и вернуть файлы к контрольной точке. Откат сохраняет историю чата и останавливается при посторонних изменениях. Команды shell, действия MCP и изменения внешних сервисов не откатываются снимками файлов; правки shell проверяйте через Git diff.

## Этап B: план, разрешения, память и контекст

Переключатель в поле ввода содержит «План», «Спрашивать», «Авто» и Bypass. План допускает исследование и Tasks, но не правки проекта. `submit_plan` показывает план и кнопку «Утвердить и выполнить». Tasks сохраняет список задач со статусами.

В «Доступ и LSP» задаются правила allow/ask/deny для инструментов и шаблонов путей или команд. Запрет имеет приоритет над Bypass. Журнал показывает фактические решения. Команды выполняются с правами текущего пользователя Windows: это не системная песочница. Git worktree изолирует рабочую копию файлов, но не ограничивает системные права shell.

Автоматически читаются AGENTS.md, CLAUDE.md и `.claude/rules`. При чтении/изменении вложенного файла добавляются инструкции его каталогов. Память проекта редактируется в «План и память», память специалистов — в профилях. Модель может сохранять устойчивые выводы инструментом Memory.

Индикатор контекста приблизительный: он использует длину сериализованного запроса, а не данные биллинга провайдера. Ранняя история и завершённые раунды инструментов автоматически суммируются; ручное сжатие доступно кнопкой «Контекст» после ответа. Все оригинальные сообщения и результаты сохраняются. Сводка тоже требует обращения к выбранной модели.

Сообщения во время работы попадают в очередь уточнений. Агент получает их после текущего запроса/набора действий. Кнопка побочного чата создаёт отдельный разговор с недавним контекстом; исходный агент продолжает работу. Effort задаётся для сессии или по умолчанию: Авто / Низкий / Средний / Высокий. В API передаётся `reasoning_effort`; «Авто» не добавляет параметр. Если шлюз его не поддерживает, отображается его ошибка. Usage и цена отсутствуют.

## Этап C: интернет, Git, агенты, скиллы, MCP

WebSearch ищет через публичный MCP endpoint Exa и возвращает источники; его доступность зависит от сервиса. WebFetch читает ограниченный текстовый ответ публичного HTTP(S)-адреса. Локальные адреса открываются инструментом Preview.

Preview запускается в изолированном Chromium без Node, в отдельной непостоянной сессии. Агент может открыть HTTP(S)-страницу, получить DOM, нажать элемент, заполнить поле, прочитать консоль и сделать скриншот. Dev server запускается через Bash/PowerShell в фоне. «Предпросмотр» показывает ту же страницу справа. Это браузерный доступ, не управление Windows-приложениями.

«Git и проверки»: status, diff, log, worktree, коммит выбранных файлов, push в origin, черновик PR и CI. Нужен установленный Git; для PR/CI — GitHub CLI (`gh`) и выполненный `gh auth login`. Создание worktree начинает от HEAD; незакоммиченные правки исходной папки не переносятся. Агент может выбирать отдельный worktree для субагента. Автоисправление CI включается отдельно для сессии, проверяет CI раз в минуту и запускает локальное исправление при новом падении; автоматического коммита/push оно не делает.

Agent / delegate_tasks запускают до трёх параллельных запросов специалистов, до шести агентов на ответ и до двух уровней вложенности. Профили содержат инструкции, разрешённые инструменты и память. Агент выбирает делегирование по задаче; фоновые агенты не блокируют основной ответ. AgentStatus возвращает фактические результаты, AgentMessage передаёт уточнение. Остановленного пользователем агента может возобновить только явное сообщение пользователя. После перезапуска приложения незавершённая работа помечается остановленной; история сохраняется.

Skills: каталог описаний доступен модели, `Skill` загружает инструкции по необходимости. Работают проектные назначения и явные `@имя`, `/имя`, `$имя`, references, `context: fork`, профиль `agent`, `allowed-tools`. Разрешения скилла пересекаются с ограничениями профиля. Динамические команды сначала возвращаются модели и выполняются через Bash с общими разрешениями; затем реальные результаты подставляются в инструкции. Связанные текстовые скрипты импортируются как файлы скилла и запускаются только через инструменты команд. Бинарные пакеты и плагины Claude Code не устанавливаются автоматически.

MCP поддерживает stdio и Streamable HTTP, OAuth/bearer, tools, resources/templates/read и prompts/get. В «Ресурсы MCP» можно читать данные и передавать их в чат. Form elicitation отображается в чате и поддерживает строки, числа, boolean, обычный и множественный выбор. Формы проверяются по JSON Schema и закрываются при отмене. Контексты запросов разных чатов не смешиваются. Для большого каталога `ToolSearch` загружает подходящие определения по запросу, чтобы не отправлять все схемы сразу.

## LSP и зависимости

Встроены TypeScript/JavaScript LSP: definition, references, hover, document/workspace symbols и diagnostics. Другой установленный stdio language server добавляется JSON-настройкой в «Доступ и LSP»: `id`, `command`, `args`, `extensions`, при необходимости `languageId`.

Git, Git Bash, `gh` и языковые серверы других языков — внешние зависимости. Приложение сообщает об их отсутствии. PowerShell, TypeScript LSP, ripgrep, редактор и PTY доступны в Windows-сборке. Модель должна поддерживать OpenAI-compatible tool calling; набор инструментов реализован приложением, а не появляется автоматически от самого API.

Адаптер поиска и подход к CRLF опираются на [OpenCode](https://github.com/anomalyco/opencode) под MIT; лицензия включена в `THIRD_PARTY_NOTICES.md`. Это отдельный открытый проект, не форк внутренней реализации Claude Code. UI-референсы собраны в [приватном поиске Lazyweb](https://www.lazyweb.com/agentic-search/6bb4bafd-984a-4194-936b-eada6a0bd235).

Проверки используют временные проекты/профили, mock API и локальный MCP-сервер. Сохранённый ключ пользователя не использовался. Реальное создание PR и CI на пользовательском GitHub не выполнялось; эти действия требуют настроенного `gh`.
