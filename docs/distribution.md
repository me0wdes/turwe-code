# Windows, macOS и GitHub

Turwe Code собирается из одного исходного проекта. Для Windows выпускается переносимый EXE x64; для macOS — отдельные DMG и ZIP для Apple Silicon (`arm64`) и Intel (`x64`). Приложение хранит проекты, историю и ключи на компьютере пользователя. Чужой API-ключ в сборку не включается.

## Готовые сборки

Публичный репозиторий: [me0wdes/turwe-code](https://github.com/me0wdes/turwe-code). Готовые файлы находятся в [GitHub Releases](https://github.com/me0wdes/turwe-code/releases). Пользователь скачивает EXE или подходящий DMG; устанавливать Node.js и собирать исходники ему не нужно. Автоматический ZIP исходников GitHub не является готовым приложением. Для скачивания вход в GitHub не требуется.

Workflow `.github/workflows/build-desktop.yml` запускается при push в `main`, отправке тега `v*` или вручную в Actions. Для новой версии он устанавливает зависимости из lock-файла, запускает тесты, проверяет нативные инструменты под Electron, собирает приложение и открывает готовую сборку с временным профилем. Три независимые машины: Windows x64, macOS Apple Silicon, macOS Intel. После успешных проверок всех трёх платформ workflow проверяет комплект из пяти файлов, создаёт SHA256SUMS.txt и публикует их одним Release. При ошибке на любой платформе обновление пользователям не предлагается. Уже опубликованные версии не пересобираются. Артефакты проверок сохраняются на 14 дней.

Для следующего обновления выполните `npm version patch --no-git-tag-version`, внесите описание в `docs/release-notes.md`, закоммитьте исходники и отправьте `git push origin main`. Номер версии в интерфейсе берётся из package.json. При использовании тега его версия должна совпадать с package.json. Обычный push с прежним номером не переиздаёт установленную версию.

## Уведомления об обновлениях

Приложение обращается только к публичному `api.github.com/repos/me0wdes/turwe-code/releases/latest` через 15 секунд после запуска и каждые 6 часов. Проверка не отправляет ключи API, проекты, историю или данные пользователя. Раздел «Настройки → Интерфейс» позволяет проверить вручную. Несколько одновременных проверок объединяются; тайм-аут сети — 15 секунд. Ошибка сети показывается в настройках и не выдаётся за отсутствие новой версии.

В уведомлении «Скачать» открывает прямой HTTPS-адрес EXE или DMG этой архитектуры в системном браузере. Проверяется точное имя файла и принадлежность GitHub Releases этого репозитория. Это автоматическое уведомление и скачивание по кнопке; замена приложения пока выполняется пользователем. Для обновления без ручной замены нужны Windows-установщик NSIS и стабильная Developer ID подпись на Mac. Текущий выпуск сохраняет переносимый Windows EXE и ad-hoc DMG.

## Сборка на своём компьютере

Требуется Node.js 24 и npm. Выполняйте `npm ci` на той системе и архитектуре, для которой собираете. Установочный скрипт отдельно загружает runtime Electron. Не копируйте `node_modules` между Windows и Mac или между Intel и Apple Silicon.

```sh
npm ci
npm test
npm run native:check
```

Затем выполните подходящую команду:

| Машина сборки | Команда | Результат в `release/` |
| --- | --- | --- |
| Windows x64 | `npm run package:win` | `Turwe-Code-<версия>-Windows.exe` |
| Mac с Apple Silicon | `npm run package:mac:arm64` | `Turwe-Code-<версия>-macOS-arm64.dmg` и `.zip` |
| Mac с Intel | `npm run package:mac:x64` | `Turwe-Code-<версия>-macOS-x64.dmg` и `.zip` |
| Любой из этих Mac | `npm run package:mac` | DMG и ZIP текущей архитектуры |

После сборки `npm run smoke:package` запускает готовое приложение с отдельным временным профилем, проверяет загрузку и отсутствие сохранённого ключа. Отчёт и снимок окна находятся в `release/smoke/`. Команда не проверяет реальные ответы провайдера или авторизацию MCP.

## Нативные зависимости

В `build` сохранены `electronDist: node_modules/electron/dist` и `npmRebuild: false`. `node-pty` 1.1 использует Node-API и включает готовые бинарники Windows x64, macOS x64 и arm64. Каждый пакетный скрипт сначала **в реальном Electron** запускает PTY и проверяет исполняемые файлы FFmpeg/ripgrep. Несовпадающая платформа или архитектура останавливает сборку. Это также выявляет пропущенные optionalDependencies или установочные скрипты.

При смене Electron/нативной зависимости или отсутствии подходящей готовой сборки выполните `npm run native:rebuild`, затем снова `npm run native:check`. Пересборка требует инструментов C++ соответствующей системы (Xcode Command Line Tools на Mac; Visual Studio Build Tools на Windows). Успешный `require()` в обычном Node.js не заменяет проверку Electron. Бинарники node-pty, FFmpeg, ripgrep и языкового сервера выносятся из ASAR.

`scripts/prepare-native.cjs` исправляет права на macOS `spawn-helper` из npm-пакета node-pty 1.1.0: upstream поставляет его без execute-bit. Это выполняется после `npm ci` и перед нативной проверкой, до упаковки и подписи. Установленное приложение не меняет собственную подпись или права и не требует для этого администратора.

## Подпись и первый запуск

Сейчас Windows EXE без сертификата подписи; Windows может показать SmartScreen. macOS использует локальную подпись ad-hoc (`identity: "-"`, `hardenedRuntime: false`), без сертификата Developer ID и notarization. Она не подтверждает автора приложения; Gatekeeper может заблокировать скачанную сборку. Для публичного выпуска с обычным запуском нужно подключить Developer ID, hardened runtime, подходящие entitlements и notarization на Mac. Сертификаты и Apple credentials должны находиться в GitHub Secrets, а не в исходниках. Текущий workflow не требует и не использует эти секреты.

На Mac приложение переносится из DMG в Applications. Если система отклоняет непроверенную сборку, доверенный пользователь может разрешить её через системный экран «Конфиденциальность и безопасность». Полноценную проверку подписанного публичного выпуска нужно проводить отдельно на другом Mac.

Данные располагаются в `%APPDATA%/Turwe Code` на Windows и `~/Library/Application Support/Turwe Code` на Mac. При переносе на другой компьютер ключ вводится заново; локальная защита ключа привязана к системному хранилищу исходного компьютера.

## Перед публикацией исходников

`.gitignore` исключает зависимости, сборки, временные профили, `.env` и распространённые форматы сертификатов. Сохраняйте API-ключи только через настройки приложения; не добавляйте реальные профили или дампы запросов в репозиторий. В исходники входят `package-lock.json`, `public/`, `src/`, `electron/`, `scripts/`, `tests/`, документация и workflow.

Лицензия самого Turwe пока не выбрана. Публичный репозиторий сам по себе не предоставляет лицензию на повторное использование. До общего релиза нужно выбрать условия распространения и проверить notices сторонних ресурсов; `THIRD_PARTY_NOTICES.md` уже содержит адаптацию OpenCode, а FFmpeg и прочие поставляемые компоненты имеют собственные условия.
