# Проверка подключения Figma MCP

Дата: 5 октября 2026. Изменения пока локальные, версия приложения 0.6.17.

## Что исправлено

- OAuth-регистрация выбирает доступный способ аутентификации по метаданным сервера. Ранее всегда отправлялся `none`, которого нет в текущих метаданных Figma. Поддерживаются `none`, `client_secret_basic`, `client_secret_post`; неподдерживаемые методы дают явную ошибку. Идентичность клиента остаётся Turwe Code.
- Диагностика различает регистрацию клиента, обмен кода на токен, ошибки DNS, отказ соединения, HTTP-ошибки и неизвестную причину. Тела ответов, ключи, коды авторизации и секрет клиента не попадают в диагностику. Ошибки OAuth сохраняют классы SDK для восстановления после `invalid_client` и `invalid_grant`.
- Карточка и результат инструмента содержат согласованные сведения; агент получает указание объяснять подтверждённые факты, не выдумывать настройки аккаунта и не переключаться на Desktop без выбора пользователя.
- Режим Figma определяется адресом, а не произвольным названием коннектора. Для локального адреса выбирается вход без OAuth, включая `localhost` и завершающий слеш. Существующие сохранённые способы входа и секреты сохраняются.

## Проверено

- Полный набор: **311 passed, 1 skipped**; пропущена проверка POSIX process group на Windows.
- `npm run build`: успешно. Сохранилось существующее предупреждение о размере JS-бандла.
- Регрессионные сценарии: отказ регистрации 403 до открытия браузера; DNS и 503 без выдуманного требования одобрения; выключенный Desktop; полный OAuth с PKCE, секретом зарегистрированного клиента и выдачей токена; сохранение токенов, refresh, повторный вход, отмена и очистка слушателя callback; HTTP/SSE-лимиты и передача редиректов SDK.
- Electron 44.5.1 на Windows, отдельный тестовый профиль и системное шифрование, без пользовательских токенов: текущий Remote отвечает **HTTP 403 на регистрации Turwe Code**. Браузер входа не открывается. `127.0.0.1:3845` отвечает отказом соединения; доступ к файлам Figma не подтверждён.

## Внешние условия

Для Remote Figma допускает клиентов из своего каталога; новый клиент подключается через заявку разработчика. Это не настройка Security / Apps пользовательского аккаунта. [Официальная инструкция Remote](https://developers.figma.com/docs/figma-mcp-server/remote-server-installation/).

Для Desktop необходимо открыть файл в Figma Desktop, включить Dev Mode и **Enable desktop MCP server**, после чего повторить подключение. Адрес — `http://127.0.0.1:3845/mcp`. [Официальная инструкция Desktop](https://developers.figma.com/docs/figma-mcp-server/local-server-installation/).

Реальный OAuth-вход в аккаунт и нативная macOS в этой проверке не выполнялись. Подключение по разрешению Figma не подменяется чужим client ID.
