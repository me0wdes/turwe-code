# Turwe Code для Windows и macOS

Локальное рабочее пространство для кодинга: проекты, сессии, редактор, терминал, изменения и браузер рядом с разговором. Две тёмные темы — ChatGPT и Claude Code, переходы Fluid Functionalism и звуки Meowdes Refs. В версии 0.6.0 добавлены инструменты разработки и этапы A–B–C аудита.

## Запуск

**Скачать:** [последний выпуск для Windows и macOS](https://github.com/me0wdes/turwe-code/releases/latest).

**Windows:** откройте файл `Turwe-Code-<версия>-Windows.exe` из последнего выпуска в Releases. Установка не нужна. Данные сохраняются в `%APPDATA%/Turwe Code` и остаются после закрытия переносимого приложения. Если запущена предыдущая версия, сначала закройте её: приложение разрешает только одно окно процесса.

**macOS:** выберите `macOS-arm64.dmg` для Apple Silicon (M1 и новее) или `macOS-x64.dmg` для Intel. Перенесите приложение из DMG в Applications; данные сохраняются в `~/Library/Application Support/Turwe Code`. Сборки используют ad-hoc подпись, без Apple notarization: первый запуск может потребовать разрешения в «Конфиденциальность и безопасность». Подробности — [Windows, macOS и GitHub](docs/distribution.md).

**Обновления:** приложение проверяет GitHub Releases при запуске и каждые 6 часов. Уведомление предлагает скачать файл для вашей ОС. Ручная проверка — Настройки → Интерфейс → Обновления приложения. Закройте старую версию перед заменой; история и настройки сохранятся. Для выпуска обновления увеличьте версию в `package.json` и `package-lock.json` (`npm version patch --no-git-tag-version`) и отправьте изменения в `main`: GitHub соберёт и проверит все платформы, затем опубликует Release.

Изменения публикуются пакетами по пять законченных улучшений или по прямой команде владельца. Текущий пакет: [неопубликованные изменения](docs/pending-updates.md).

1. «Новая сессия» открывает стартовый экран: выберите проект, создайте папку или начните без проекта. Чат сохраняется при первом сообщении. Для рабочих файлов агент создаст отдельную папку в системной «Документы/Turwe/Projects»; чтение контекста из других папок остаётся доступным через разрешения. Кнопка в правой рабочей панели открывает рабочую папку в Проводнике Windows или Finder на Mac.
2. Плюс над чатом открывает список панелей: редактор, терминал, изменения, план и память, браузер, Git, профили, правила доступа, LSP и ресурсы MCP. Одновременно можно открыть любые две. Вложения добавляются через отдельный плюс внутри поля ввода.
3. Выберите модель и отправьте задачу. Enter отправляет, Shift+Enter переносит строку, Esc останавливает ответ.
4. Ctrl+N открывает стартовый экран без создания пустого чата, Ctrl+K ищет по названиям и содержимому; на Mac используются Cmd+N и Cmd+K. Чаты с историей, текстом черновика, вложениями или очередью сохраняются отдельно. В меню строки можно переименовать или архивировать сессию. В архиве доступны восстановление и удаление навсегда с подтверждением.
5. В нижней части боковой панели находятся настройки соединения, моделей, effort, темы, анимаций и звука. Подробности новых функций: [руководство 0.6.0](docs/coding-workspace.md).

Во время ответа новые сообщения попадают в очередь над полем ввода. Кнопка «Скорректировать» передаёт выбранное сообщение как дополнение к текущей задаче: генерация ответа обновляется сразу, выполняемое действие сначала завершается. Остальные сообщения сохраняют порядок. Изменение текста и удаление находятся в меню с тремя точками. После остановки или перезапуска очередь можно продолжить вручную. В 0.6.13 очередь обозначена стопкой слоёв, а «Скорректировать» — стрелкой с поворотом вправо из Mishanaer; следующее сообщение использует Filled, ожидающие — Stroke.

Интерфейс использует **Mishanaer Round**: обычные иконки — Stroke, выбранные разделы, включённые переключатели и открытые меню — Filled. SVG включены в сборку и работают без интернета. Переход учитывает настройку уменьшения движения. Источники и соответствия действий находятся в `src/icons/source-manifest.json`. В 0.6.1 переключатель боковой панели оставлен только в заголовке окна: иконка с узкой боковой секцией адаптирована из Mishanaer и заполняется при открытой панели.

## Индикатор ожидания · 0.6.15

Во время подключения и генерации ответа показывается одна из 20 шуточных фраз. Первая выбирается случайно, следующие меняются каждые 4 секунды с вертикальным переходом и бликом. SVG-значок перетекает между кругом и восьмёркой по приложенному образцу. Ширина строки остаётся постоянной; при отключённых анимациях или уменьшении движения фраза и значок статичны. При скрытии окна таймер приостанавливается. Фразы существуют только в интерфейсе, не записываются в историю и не отправляются модели.

## Панель и начало чата · 0.6.14

- Боковая панель раскрывается и скрывается короткой пружиной с лёгким отскоком. Список остаётся смонтированным, сохраняя раскрытые группы и прокрутку; скрытая панель исключена из клавиатурной навигации. Настройка анимаций и системное уменьшение движения отключают переход.
- Управление звуком находится только в «Настройки → Интерфейс».
- При запуске и после архивации последнего чата пустые сессии автоматически не создаются. Новый чат и отправка через публичный IPC требуют существующий проект; старые записи без проекта остаются в истории.

## Браузер · 0.6.12

- Компактная панель: назад, вперёд, обновить/остановить, адресная строка и меню. В строке виден домен; при редактировании — полный адрес. Домены и `localhost:порт` можно вводить без схемы.
- Стартовый экран без подставленного адреса. Загрузка обозначается полосой; ошибка сети показывает сообщение и повторную попытку. Страница занимает оставшееся место панели.
- В меню доступны поиск по странице, масштаб 50–200%, копирование ссылки, сохранение PNG, печать и открытие в системном браузере. Консоль скрыта до запроса; её можно обновить и очистить.
- Ctrl/Cmd+L выбирает адрес, Ctrl/Cmd+F открывает поиск, Ctrl/Cmd+R обновляет страницу; Ctrl/Cmd с плюс/минус/0 управляет масштабом. Enter/Shift+Enter в поиске переходят между совпадениями.
- Меню открывается поверх снимка текущей страницы, сохраняя её позицию. После закрытия возвращается та же интерактивная страница. У каждого чата свой браузер в текущем запуске приложения; команда агента продолжает автоматически открывать его в виджете.

## Виджеты результатов и команды без проекта · 0.6.11

- Успешный `Preview navigate` сразу открывает сайт в правом виджете, включая конечный адрес после перенаправления. Повторный переход использует тот же браузер.
- Правки файлов открывают «Изменения». Фоновая команда или `Bash/Process` с `show: true` показывает вывод нужного процесса; `FileRead` с `show: true` открывает файл в редакторе. Обычное чтение контекста не переключает панели.
- Остаётся максимум два виджета. Если места нет, заменяется панель, отличная от редактора. Несохранённый файл сохраняется; его переключение требует сначала сохранить черновик.
- Результат фоновой сессии ждёт открытия её чата. Старые действия, ошибки и обновления состояния не открывают закрытый виджет повторно.
- «Новая сессия» открывает отдельный стартовый экран. Можно выбрать проект или сразу отправить сообщение без него; запись в истории появляется после отправки, а повторные нажатия не создают пустых чатов. Для рабочих файлов агент может вызвать `CreateWorkspace`: приложение создаст отдельный проект в системной папке «Документы/Turwe/Projects». Первая запись через `FileWrite` также создаёт эту папку автоматически. Обычный разговор и чтение справки не создают папок.
- `FileRead` принимает абсолютные пути и `../` к контексту вне проекта; `Glob` и `Grep` поддерживают `path` для поиска в другой папке. Файловые изменения остаются в рабочем проекте. Внешний файл можно показать в редакторе только для чтения. `Bash`, `Process`, терминал и `Preview` доступны без проекта; до создания рабочей папки команды стартуют в домашней папке. Действуют выбранный режим разрешений и обычные права пользователя ОС.

## Подключения и скиллы из чата · 0.6.10

- Напишите «Подключи Figma» или попросите выполнить задачу в ещё не подключённом сервисе. Агент может подготовить MCP-подключение сам: карточка показывает сервис, адрес и действие. Действует выбранный режим разрешений.
- OAuth открывает системный браузер; карточка показывает ожидание входа, позволяет повторно открыть браузер и остановить попытку. После обнаружения инструментов агент продолжает исходный запрос автоматически.
- Сохранённые MCP-серверы, включая stdio, можно подключать по имени через чат. Для нового HTTP-сервера нужен точный адрес MCP. Пароли и токены не запрашиваются у модели; bearer-токены вводятся в настройках коннектора.
- «Создай скилл проверки интерфейса для проекта» создаёт SKILL.md с предпросмотром. По умолчанию скилл сохраняется для выбранного проекта и назначается ему; по запросу можно сохранить в общей библиотеке. Готовый скилл можно сразу использовать через инструмент Skill или вызвать позже через `@имя`.
- Установка скилла по GitHub-ссылке тоже получила карточку. Повторное создание не перезаписывает другой скилл с тем же именем; повторное подключение сохраняет авторизацию.
- Figma Remote допускает клиентов из каталога Figma. При отказе регистрации карточка показывает этап и HTTP-код; заявку для нового приложения подаёт его разработчик. Ошибки сети и выключенный Figma Desktop диагностируются отдельно. Локальный сервер должен быть включён в настольной Figma; набор его инструментов может отличаться от Remote.
- [Проверки и ограничения версии 0.6.10](docs/chat-setup-0.6.10.md).

## Контекст проекта и инструменты · 0.6.9

- Уже первый запрос получает рабочую папку, ОС, оболочку, список файлов и ограниченные выдержки README/PROJECT/ПРОЕКТ. Инструкции загружаются из AGENTS.md, CLAUDE.md, `.claude/CLAUDE.md` и правил. Контекст обновляется перед запросами и использует папку текущего worktree. Автоматическое чтение учитывает разрешения; файлы с ключами и произвольные конфигурации не подгружаются.
- PowerShell возвращает UTF-8 и настоящий код возврата внешней команды. Ошибки запуска, ненулевой код и таймаут передаются агенту как ошибки; остановка процесса дожидается завершения. Большой вывод сокращается без повреждения JSON.
- Grep, как и Glob, находит локальные файлы, исключённые из Git, сохраняя исключения для зависимостей и секретных файлов. Ошибки поискового MCP больше не считаются результатом поиска.
- Приоритет правил: deny, затем ask, затем allow. Остановка ответа по лимиту или фильтру не считается завершением работы и не запускает незавершённый набор инструментов.
- [Что перенесено из документации и открытых реализаций](docs/agent-runtime-0.6.9.md).

## Поиск и прокрутка чата · 0.6.8

- После короткой реплики «ищу / проверю» без вызова инструмента приложение один раз продолжает тот же запрос. Повторное обещание заканчивается явной ошибкой, а не статусом выполненной задачи. Уточняющие вопросы, ограничения и обычные ответы не требуют такого продолжения.
- В журнале WebSearch показывается только фактический поиск и его запрос. Для картинок модель анализирует вложение и при необходимости ищет по текстовым признакам; обратный поиск изображения не подключён.
- Если API сообщает о вызове инструмента, но не присылает его параметры, приложение показывает ошибку протокола.
- Кнопка перехода вниз появляется только при прокрутке выше последних сообщений. Изменение размера окна и высоты чата сохраняет следование за ответом; чтение старых сообщений не прерывается.

## Две рабочие панели · 0.6.6

Перетащите панель за заголовок к левому, правому, верхнему или нижнему краю рабочей области панелей: подсветка покажет, куда она встанет. То же расположение можно выбрать через три точки в её заголовке; там же доступны обмен местами и одинаковый размер. Esc отменяет перетаскивание. Потяните разделитель между панелями или их левую границу, чтобы изменить размер. Разделители доступны с клавиатуры: стрелки меняют размер, Home/End устанавливают пределы; двойной щелчок между панелями делит место поровну.

Набор инструментов, порядок, ширина и пропорции сохраняются отдельно для каждого проекта (и рабочей копии Git). Перестановка сохраняет несохранённый текст редактора, активный терминал и загруженную страницу. На узком окне панели размещаются друг над другом; в заголовке одной открытой панели появляется плюс для добавления второй. Закрытие панели терминала не останавливает процесс — для этого есть кнопка «Остановить».

## Сообщения в чате · 0.5.7


Сообщения пользователя отображаются в облачках справа, а ответы ИИ — свободным текстом слева. Имена, аватарки, модель над ответом и дата начала диалога убраны. Вложения и кнопки действий выровнены вместе со своим сообщением; у сообщения только с вложением нет пустого облачка. Редактирование, копирование, действия агента и опросы сохраняются. Новый вид работает в обеих темах.

## Тёмные темы · 0.5.11

В «Настройки → Интерфейс → Тема приложения» доступны ChatGPT (по умолчанию) и Claude Code. Прежняя тема Turwe автоматически заменяется на ChatGPT, остальные настройки и история сохраняются. Карточки показывают миниатюру каждой палитры; выбор применяется сразу, сохраняется локально и восстанавливается после перезапуска. Можно переключать темы стрелками клавиатуры. Цвета распространяются на чат, меню, настройки, файлы, скиллы, коннекторы и субагентов, включая анимированную надпись Turwe code. Размер окна настроек не меняется.

Палитры сверены 4 октября 2026 с опубликованными стилями [Claude Code](https://claude.ai/code) (общие тёмные CDS-токены Claude, `data-color-version="v2"`) и [ChatGPT](https://chatgpt.com/) (нейтральный вариант без персонального цветного акцента). Для Claude использованы текущие `bg-100`, `bg-200`, `bg-000`, `text-100/200/400` и `brand-100`; отдельный авторизованный экран Code на этом компьютере не проверялся. Определения и соответствия цветов находятся в `src/themes.css`.

## Действия в чате · 0.5.5

Комментарии агента, вызовы инструментов и итоговый ответ отображаются в порядке выполнения. Серые строки с иконками показывают чтение файлов, скиллы, интеграции MCP и субагентов; параметры и результат раскрываются нажатием. Во время работы иконка пульсирует, а ошибки, отказ в разрешении и остановка имеют отдельные состояния. У субагентов та же хронология. Действия сохраняются в истории, текст при потоковой загрузке и повторе не дублируется. Анимации учитывают настройку уменьшения движения.

## Файлы проекта · 0.5.4

Левая обводка панели файлов убрана. Стрелка «На уровень выше» появляется только во вложенных папках. Кнопка «Открыть в проводнике» в верхней панели открывает корневую папку текущего проекта; когда проект не выбран, кнопка скрыта. Если папка недоступна, приложение показывает уведомление об ошибке.

## Боковая панель и архив · 0.5.3

У папок и пункта «Скиллы» больше нет счётчиков, расстояние между папками сокращено. В архиве при наведении на чат появляются иконки восстановления и удаления. Удаление навсегда требует подтверждения: история и черновик исчезают из архива и поиска; проекты и остальные сессии сохраняются. Если сохранить изменение не удалось, чат остаётся в архиве. Декоративные текстовые стрелки заменены SVG-иконками Mishanaer.

## Вложения и уведомления · 0.5.2

Исправлена вставка через «+ → Из буфера обмена» для текущего Electron. Изображения распознаются по содержимому: например, JPEG, сохранённый под расширением PNG, теперь импортируется с корректным типом. Повреждённые файлы по-прежнему отклоняются.

Файлы можно перетаскивать на всю область чата. Зона плавно появляется и исчезает, показывает ограничение количества или недоступность чата; во время обработки виден текущий файл. При ошибке одного файла остальные вложения в наборе сохраняются. Ошибки появляются сверху на 6 секунд, таймер приостанавливается при наведении, фокусе и скрытии окна. Подсказка про Enter под полем убрана; сочетания клавиш работают как раньше.

## Каталог моделей · 0.6.7

- Настройки разделены на «Подключение», «Модели» и «Интерфейс». Размер окна постоянный; исправлены внешние и внутренние скругления переключателя и отступ над выпадающим списком.
- «Мои модели» — сохранённый список для текущего адреса API. По умолчанию у ai.lab.pics включены Claude Opus 5.5 (`claude-opus-5-5`) и Claude Sonnet 5 (`claude-sonnet-5`). GLM больше не добавляется автоматически; ранее выбранные вручную модели сохраняются.

## Режимы разрешений

В поле ввода выбирается режим для этого чата и его субагентов:

- **Ручной** — спрашивает перед каждым вызовом инструмента, включая чтение и ранее разрешённые действия.
- **Упрощённый** — выполняет ранее разрешённое, новые действия подтверждает пользователь.
- **Авто** — выполняет ранее разрешённое, остальные действия проверяет отдельная модель. Разрешение модели действует один раз; отказ, ошибка, тайм-аут или неполный ответ не запускают действие.
- **Ебашим на все бабки** — выполняет доступные инструменты без подтверждений, проверки моделью и правил разрешений проекта. Проверка аргументов, границы файловых инструментов, ограничения профиля и системные права сохраняются.

**Настройки → Модели → Модель проверки действий**: автоматический выбор ищет Haiku в сохранённом списке текущего API, затем Sonnet. Можно выбрать другой сохранённый ID, включая псевдоним провайдера. Модель проверки получает последние запросы пользователя, описание инструмента и параметры одного действия; инструментов у неё нет. Если подходящая модель не настроена, автоматическая проверка сообщает об этом и не запускает действие.

**Разрешить один раз** не создаёт постоянного разрешения. Меню **Всегда разрешать…** предлагает разрешить выбранный инструмент во всех чатах текущего проекта (включая worktree) либо во всех проектах. В ручном режиме такой выбор явно переключает чат в упрощённый; возвращение в ручной снова включает подтверждение каждого действия. Разрешения сохраняются после перезапуска и учитывают идентичность инструмента и подключения MCP. **Запомнить только этот вызов** сохраняет более узкое разрешение: те же параметры и рабочая папка. В «Доступ и LSP» отдельно сбрасываются разрешения проекта/чата и всех проектов. Хранилище содержит хеши, решения проверяющей модели остаются разовыми. Явные запреты, правила ask и ограничения профиля сохраняют приоритет.

В обычных режимах явные правила `deny` и `ask` имеют приоритет над запомненными разрешениями; ручной режим не пропускает даже `allow`. План вынесен отдельным пунктом: позволяет исследование и Tasks, но запрещает правки. `ask_user` всегда ждёт человека. При смене режима незавершённая проверка отменяется и действие оценивается заново. Файлы без разрешения не подгружаются в контекст автоматически: агент читает их через проверяемые инструменты.

## Скиллы и модели

- «Скиллы» в боковой панели: создание, редактирование и импорт `SKILL.md`. Кнопка поиска в папке импортирует `.claude/skills/*/SKILL.md` и `.agents/skills/*/SKILL.md` выбранного проекта. Импорт копирует инструкции и связанные текстовые файлы; исходники на диске не изменяются. Повторный импорт того же имени в ту же библиотеку обновляет сохранённую копию и справку.
- Выберите проект в библиотеке и включите переключатель на карточке. Подключённые инструкции добавляются к каждому новому сообщению этой папки. Для других папок назначения независимы.
- `@имя`, `/имя` или `$имя` в сообщении вызывают скилл явно. Подсказки появляются при вводе. `$ARGUMENTS`, `$ARGUMENTS[0]` и `$0` подставляют аргументы. `disable-model-invocation: true` разрешает только ручной вызов, `user-invocable: false` оставляет только назначение проекту. Не пишите вызов внутри примера кода.
- Инструкции и справка сохраняются вместе с отправленным сообщением. Изменение или удаление скилла не переписывает историю и контекст повтора. Для использования новой версии после изменения начните новую сессию, чтобы старые инструкции не оставались в предыдущих сообщениях.
- Поддерживаются инструкции и прямые Markdown-ссылки на локальные `.md`, `.txt`, `.json`, `.yaml`, `.yml`, `.csv` внутри папки скилла. Ограничения: 64 000 символов SKILL.md, 12 файлов справки, 192 000 символов суммарного контекста скиллов.
- В 0.6.0 работают `context: fork`, `agent`, `allowed-tools`, загрузка по описанию и динамические команды через Bash с разрешениями. Скрипты импортируются как текстовые файлы скилла; установка сама их не исполняет. Подробности — в [руководстве](docs/coding-workspace.md).
- Список моделей управляется в «Настройки → Модели» и сохраняется отдельно для каждого адреса API. В выпадающем меню чата есть переход «Управление моделями…». Поиск не добавляет модели автоматически.
- «Добавить свою» в разделе «Модели» сохраняет произвольный ID и необязательное название. В существующей сессии модель выбирается в поле ввода сообщения.
- **4 октября 2026** прямой запрос с ID `claude-opus-5-5` через сохранённый ключ успешно вернул **HTTP 200** и ответ **OK.**, хотя `/models` перечислял только Base, Cheap, Frontier.

## Субагенты · 0.5.0

Напишите, например: «Раздели проверку интерфейса и API между двумя субагентами, затем собери результат». Модель вызывает delegate_tasks, запускает отдельные диалоги через ваш API и получает реальные результаты помощников. Удобно для независимых частей задачи; простые вопросы агент решает сам.

Над вводом появляется сворачиваемый виджет. В нём видны основной агент, задачи помощников и их текущие действия. Пульсирующая точка означает работу, жёлтая — вопрос или запрос разрешения. Нажмите строку, чтобы открыть вывод, ответить, разрешить действие или остановить этого агента. «Стоп» основного ответа останавливает всё дерево. В панели «Агенты этого ответа» доступны все помощники, включая результаты старых сообщений.

Субагенты наследуют проект, вложения, снимок подключённых скиллов и текущий режим подтверждений чата. История сохраняется после закрытия приложения; при повторе прерванного запроса родитель получает уже выполненные результаты. Выключатель: «Настройки → Интерфейс → Субагенты».

Лимиты: 3 параллельных запроса субагентов, 6 помощников на один ответ и 2 уровня вложенности. Каждый помощник расходует отдельные запросы API. Модель должна поддерживать вызов инструментов; встроенные инструменты записи файлов и shell не добавляются. Проверка 4 октября 2026: Opus 5.5 успешно выполнил реальное параллельное делегирование через ai.lab.pics/v1.

## Возможности и границы

- Проекты, история, черновики, настройки и архив сохраняются локально.
- Несколько сессий могут получать ответы независимо; остановка относится к выбранной сессии.
- Markdown, таблицы, код и копирование текста.
- До 8 вложений; форматы и пределы перечислены выше. Файлы из панели проекта сохраняют текстовый снимок до 512 КБ каждый.
- Служебные каталоги и файлы секретов не добавляются автоматически. Нужный контекст можно читать вне проекта через разрешённые вызовы файловых инструментов; файловые правки и контрольные точки относятся к рабочей папке проекта.
- Ключ не входит в исходники и `.exe`. При смене адреса API нужен ключ для нового адреса.
- Встроены инструменты записи в проект и выполнения команд; MCP-серверы могут предоставлять дополнительные операции. Подтверждения зависят от выбранного режима чата.
- Звуки можно полностью выключить; системное уменьшение движения учитывается.

## Разработка и проверки

Node.js 24, npm. `npm ci` устанавливает версии из lock-файла и загружает Electron. Устанавливайте зависимости непосредственно на целевой системе и архитектуре.

Для видео нужен бинарный файл `ffmpeg-static`; если установочный скрипт npm заблокирован, выполните `node node_modules/ffmpeg-static/install.js`. В переносимой сборке FFmpeg уже включён и вынесен из ASAR.

- `npm run dev` — браузерный просмотр на 127.0.0.1:5186; без доступа к диску и API.
- `npm run build` — проверка TypeScript и сборка интерфейса.
- `npm start` — запуск собранного интерфейса в Electron.
- `npm test` — тесты хранения, файлов, потока, ключей и контроллера сессий.
- `node tests/interaction-preview-server.cjs` — изолированный UI-стенд с настоящим контроллером, временными данными и искусственными ответами модели; открыть `/tests/interaction-preview.html` на порту 5186. API-ключ и внешние инструменты не используются.
- `node tests/single-instance.integration.cjs` — реальный тест двух запусков Electron в отдельной временной папке.
- `npm run package:win` — переносимый Windows x64 `.exe`.
- `npm run package:mac` — DMG и ZIP для архитектуры текущего Mac; явные варианты: `package:mac:arm64` и `package:mac:x64`.
- `npm run native:check` — проверка PTY, FFmpeg и ripgrep под Electron. Выполняется перед каждой упаковкой.
- `npm run smoke:package` — запуск собранного приложения с отдельным тестовым профилем.

Workflow для трёх систем и инструкции будущей публикации находятся в [руководстве по распространению](docs/distribution.md). macOS-сборки требуют запуска на Mac; GitHub Actions предоставляет соответствующие машины.

Код в `electron` отвечает за файлы, ключ, историю и сеть; `src` — за интерфейс. Основная логика покрыта тестами, внешний шлюз проверяется отдельно. Подробности — в `docs/verification.md`.
